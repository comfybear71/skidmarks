## Cursor Cloud specific instructions

Skidmarks Studio ("planner") is a single local-first Next.js 16 (Turbopack, React 19) app. There is one service.

- Run the dev server with `npm run dev` (see `package.json`); it binds `0.0.0.0:3737`. Lint is `npm run lint`, production build is `npm run build`. No database or external service is required to boot: app state persists to the git-ignored `data/` folder (created lazily on first write), so `/`, `/lab`, `/locations`, and the JSON APIs under `/api/*` work with no env vars.
- All external keys in `.env.example` (ElevenLabs, XAI/Grok, RunPod/Comfy, Neon `DATABASE_URL`, Vercel Blob) are optional and only needed to actually run generation jobs (voice, image, video). Leave them blank for normal UI/data development.
- `src/lib/paths.ts` resolves `MOVIES_ROOT` two levels above the repo (the real PC keeps `Skidmarks/episodes` there). That folder does not exist in the cloud VM, so the Crash Lab episode shelves on `/` list empty — this is expected, not a bug.
- Dev gotcha: a compile error anywhere reachable from `/crash` surfaces as a Turbopack global overlay, so unrelated `/api/*` routes also return the 500 error page until the error is fixed or the dev server is restarted.
- Live production (`https://skidmarks-seven.vercel.app` and `https://skidmarks.aiglitch.app`) only updates when `master` deploys on Vercel. Open PR branches get SSO-protected preview URLs; they do **not** change the public site until merged.
- Intended public hostname is `https://skidmarks.aiglitch.app`. `aiglitch.app` already uses Vercel nameservers. Attach `skidmarks.aiglitch.app` under the **skidmarks** Vercel project **Settings → Domains** if it 404s `DEPLOYMENT_NOT_FOUND`.
- Cloud story GET without `folderName` returns an empty stub on purpose (so refresh does not reopen last night’s pack). Desk panels must use `crashDeskStoryFetchUrl()` after Open so Story / Storyboard / Animate load `PILOT_CORNISH_ARSEHOLE` (and every other pack) from Neon. Cast file routes fall back across shows when a thumb id lives under another `show_id` (e.g. Sunny Banks `thumb_*.png` requested as Skidmarks).
- **Do not trust desktop handover dumps** such as `CURSOR_PROMPT_FULL_PROCESS.md` until the owner pastes the file into chat and it is audited. Those “full process / rebuild / start over / clear desk” prompts are how packs have looked wiped 6–7 times. Empty Storyboard on production is almost always unmerged PR + stub GET, not deleted Blob.
- **Trusted continue prompt** (paste this, not a rebuild bible): Open pack by `folderName`. Scene kit comes from Open POST. Reload places = re-Open, not disk GET. Storyboard/Animate use `crashDeskStoryFetchUrl()` + open-story/ltx caches. Infer thin kits from speakers vs cast shelf. Never Close / New episode / clear Story / rewrite `story_json`. Never delete media (park in `_cleared/`). `saveCloudEpisodeMeta` must keep richer existing Neon story/kit. Live `skidmarks.aiglitch.app` does not change until PR #2 merges to `master`.
- This cloud VM cannot read `C:\Users\Stuie\Desktop\MY MOVIES\...`. Ask the owner to paste any local prompt/doc; do not invent its contents.
- Sunny Banks IMAGE MOTION gold (First Fleet, worked 100%): `docs/SUNNY_BANKS_IMAGE_MOTION_STANDARD.md` + `docs/SUNNY_BANKS_IMAGE_MOTION_GOLD.json`. Speaking plates: `Use the provided start image as the first frame.` + look lock + `is prominent, mouth and head move naturally while speaking` + `NAME says: "line"` + style lock. No `[VISUAL]`, no `[SPEECH]` on this Cloud gold (Bazza Pass only keeps `[SPEECH]`). Do not rebuild these. Do not write them onto a live pack unless Stuie says go.
- Storage split: locally (and in this VM) everything reads/writes disk under `DATA_DIR` (`./data`, git-ignored). The deployed Vercel app uses the cloud store only when `runningOnVercel()` + `DATABASE_URL` + `BLOB_READ_WRITE_TOKEN` are all set (`src/lib/cloudEnv.ts` `useCloudStore()`); media then lives in Vercel Blob and metadata/JSON in Neon (see `sql/`, `src/lib/neonStore.ts`, `src/lib/blobStore.ts`).
- Next.js 16 inlines `process.env.NAME` at build time. Never gate Vercel/cloud behavior on a static `process.env.VERCEL` check — live production baked that as empty, so the chrome said "localhost only" and shelves never switched to Blob. Use `runningOnVercel()` (dynamic `process.env[name]` lookup) and `connection()` in the root layout before reading env for the Vercel/localhost badge.
- Vercel filesystem: `/var/task` is read-only, so `DATA_DIR` is redirected to `os.tmpdir()` when `runningOnVercel()` is true (`src/lib/paths.ts`). Disk writes there are per-invocation scratch only; anything that must persist on Vercel has to go through Blob + Neon.
- Mobile plates: approve writes faces/places into local galleries that are gone on the next Vercel invoke. Those stills already live in Blob under the **job id** (`mobileMediaFolder` — `folderName` stays empty until screenplay; do not set `folderName = job.id`). `compositeShotPlate` must resolve the job's approved candidate `fileName`s (`src/lib/mobilePlateMedia.ts`), not only the show shelf. `worldThumbKey` (`g:place_…`) is a local-gallery copy and is not in Blob.
- Mobile More / Not this one must **append** takes (`keepCandidateTakes`) and keep the tweak prompt on each candidate. Replacing the list or clearing the box throws away the still and the words that made it. Opening a cast/place thumb (or Undo / a take thumb) must fill the box with that still's prompt — an empty box with only the placeholder is a bug. Drop a photo back via `/api/crash/mobile/candidate-upload` — do not delete earlier stills. A later More must send the last still as the image reference (edit, not a fresh lottery) and `directorNote` must add the tweak to the look — never replace the look, and never use the vibe line as the face.
- Character plates are the series turnaround sheet (`shows/{show}/character-plates/plate_{slug}.ext`, e.g. `plate_baby.jpg`). Built after a face is picked (`POST /api/crash/mobile/character-plate`). Show-level, never episode-level. Do not overwrite an existing series sheet. Do **not** hand the sheet to `plateCastIntoGen` — it is several copies of one person and would draw doubles. Shot plates still use the single cast card.
- `/m` resumes the last job from `?job=` or `localStorage` (`skidmarks.mobile.lastJobId`). The job document lives in Neon (`mobile_jobs`); faces live in Blob under the job id. A plate/generate error must not create a new job or clear speakers. Do not tap Start directing again for an episode that already exists — that mints a new empty job and the old one stays, but the phone looks blank. If the id is in the URL and the fetch fails, show that — never a silent empty vibe.
- `/m` scrolls the **window**, not an inner pane. Do not put `overflow-y: auto` + `flex: 1` on the tree — CAST + LOCATIONS fill the screen and the swipe never reaches a scroller. Horizontal strips use `touch-action: pan-x pan-y` so a vertical flick still moves the page.
- `/m` episode: template from the locked cast + places → **AI the story** → refine → **Lock**. Pack opens in Crash Lab. Client imports `mobilePasteParse` only, never `mobilePasteScript`. Shot plates take a staging prompt (who sits, leans, walks — not a lineup in front of the still) plus the look/place words. Rebuild one plate via `POST /api/crash/mobile/plate`. Do not wipe the job. Clips follow the mp3 (`ltxDuration.ts`, safety ceiling 180s — not a 30s model cap).
- Cloud media kinds: `files.kind` covers episode media (`plates | audio | mp4`) and show-level shelves (`world | cast | character_plate | spx_sfx | spx_video`, plus `story_sfx | placeholder`). Show-level shelf rows have `episode_id = NULL` and a `show_id`; blob paths are `shows/{show}/world-cards|style-cards|character-plates|spx/...` (`showAssetPathname` in `blobStore.ts`). Human labels for these live in Neon columns (`label_name`, `label_brief`, `place_type`, `spx_id`), replacing the on-disk `manifest.json`. On cloud the resolver routes (`world-cards/file`, `style-cards/file`, `character-plates/file`, `spx/file`) and list routes stream/read from Blob+Neon via `src/lib/cloudShelf.ts`.
- Neon schema is applied by `node scripts/apply_neon_migration.mjs` (runs every `sql/*.sql` in order, idempotent). `sql/002_cloud_assets.sql` adds the show-level columns/kinds.
- Backfilling media into the cloud: run `node scripts/backfill_cloud_assets.mjs --style <id> --go` (or `--all --go`) from a machine that HAS the local `data/crash/{world-cards,style-cards,spx}/{show}` files (i.e. the PC) with `DATABASE_URL` + `BLOB_READ_WRITE_TOKEN` set. Per-pack `plates|audio|mp4` still upload via `POST /api/crash/cloud/upload` / `scripts/upload_pack_to_cloud.mjs`. `docs/CLOUD_ASSET_MAP.md` is the path/naming contract; `docs/MISSING_ASSETS.md` is a live gap snapshot.
- The cloud VM has no `MY MOVIES` tree and no source media; backfill must be run where the files live (the PC), or the files uploaded to the VM first.
