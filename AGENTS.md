## Cursor Cloud specific instructions

Skidmarks Studio ("planner") is a single local-first Next.js 16 (Turbopack, React 19) app. There is one service.

- Run the dev server with `npm run dev` (see `package.json`); it binds `0.0.0.0:3737`. Lint is `npm run lint`, production build is `npm run build`. No database or external service is required to boot: app state persists to the git-ignored `data/` folder (created lazily on first write), so `/`, `/lab`, `/locations`, and the JSON APIs under `/api/*` work with no env vars.
- All external keys in `.env.example` (ElevenLabs, XAI/Grok, RunPod/Comfy, Neon `DATABASE_URL`, Vercel Blob) are optional and only needed to actually run generation jobs (voice, image, video). Leave them blank for normal UI/data development.
- `src/lib/paths.ts` resolves `MOVIES_ROOT` two levels above the repo (the real PC keeps `Skidmarks/episodes` there). That folder does not exist in the cloud VM, so the Crash Lab episode shelves on `/` list empty — this is expected, not a bug.
- Dev gotcha: a compile error anywhere reachable from `/crash` surfaces as a Turbopack global overlay, so unrelated `/api/*` routes also return the 500 error page until the error is fixed or the dev server is restarted.
- Live production (`https://skidmarks-seven.vercel.app` and `https://skidmarks.aiglitch.app`) only updates when `master` deploys on Vercel. Open PR branches get SSO-protected preview URLs; they do **not** change the public site until merged.
- Intended public hostname is `https://skidmarks.aiglitch.app`. `aiglitch.app` already uses Vercel nameservers. Attach `skidmarks.aiglitch.app` under the **skidmarks** Vercel project **Settings → Domains** if it 404s `DEPLOYMENT_NOT_FOUND`.
- Cloud story GET without `folderName` returns an empty stub on purpose (so refresh does not reopen last night’s pack). Desk panels must use `crashDeskStoryFetchUrl()` after Open so Story / Storyboard / Animate load `PILOT_CORNISH_ARSEHOLE` (and every other pack) from Neon. Cast file routes fall back across shows when a thumb id lives under another `show_id` (e.g. Sunny Banks `thumb_*.png` requested as Skidmarks).
- Scene kit **Reload places** on Vercel must call `/api/crash/scene-kit?styleId=&folderName=` (`crashDeskSceneKitFetchUrl`). A bare GET reads disk and is always empty in the cloud. Animate / storyboard mp4 thumbs come from `GET /api/crash/comfy/ltx?styleId=&folderName=` which maps pack Blob mp4s onto story beats: named stems first (EP01 `plate_A_dark_sleep` → `A_dark_sleep.mp4`), then leftover `ltx_*_LTX_Director_*.mp4` files in filename order (EP03/EP04). Stub recipes (one empty Shot 1) expand storyboard shots from the pack’s scene-kit `plateFiles`.
- Storage split: locally (and in this VM) everything reads/writes disk under `DATA_DIR` (`./data`, git-ignored). The deployed Vercel app uses the cloud store only when `runningOnVercel()` + `DATABASE_URL` + `BLOB_READ_WRITE_TOKEN` are all set (`src/lib/cloudEnv.ts` `useCloudStore()`); media then lives in Vercel Blob and metadata/JSON in Neon (see `sql/`, `src/lib/neonStore.ts`, `src/lib/blobStore.ts`).
- Next.js 16 inlines `process.env.NAME` at build time. Never gate Vercel/cloud behavior on a static `process.env.VERCEL` check — live production baked that as empty, so the chrome said "localhost only" and shelves never switched to Blob. Use `runningOnVercel()` (dynamic `process.env[name]` lookup) and `connection()` in the root layout before reading env for the Vercel/localhost badge.
- Vercel filesystem: `/var/task` is read-only, so `DATA_DIR` is redirected to `os.tmpdir()` when `runningOnVercel()` is true (`src/lib/paths.ts`). Disk writes there are per-invocation scratch only; anything that must persist on Vercel has to go through Blob + Neon.
- Cloud media kinds: `files.kind` covers episode media (`plates | audio | mp4`) and show-level shelves (`world | cast | spx_sfx | spx_video`, plus `story_sfx | placeholder`). Show-level shelf rows have `episode_id = NULL` and a `show_id`; blob paths are `shows/{show}/world-cards|style-cards|spx/...` (`showAssetPathname` in `blobStore.ts`). Human labels for these live in Neon columns (`label_name`, `label_brief`, `place_type`, `spx_id`), replacing the on-disk `manifest.json`. On cloud the resolver routes (`world-cards/file`, `style-cards/file`, `spx/file`) and list routes stream/read from Blob+Neon via `src/lib/cloudShelf.ts`.
- Neon schema is applied by `node scripts/apply_neon_migration.mjs` (runs every `sql/*.sql` in order, idempotent). `sql/002_cloud_assets.sql` adds the show-level columns/kinds.
- Backfilling media into the cloud: run `node scripts/backfill_cloud_assets.mjs --style <id> --go` (or `--all --go`) from a machine that HAS the local `data/crash/{world-cards,style-cards,spx}/{show}` files (i.e. the PC) with `DATABASE_URL` + `BLOB_READ_WRITE_TOKEN` set. Per-pack `plates|audio|mp4` still upload via `POST /api/crash/cloud/upload` / `scripts/upload_pack_to_cloud.mjs`. `docs/CLOUD_ASSET_MAP.md` is the path/naming contract; `docs/MISSING_ASSETS.md` is a live gap snapshot.
- The cloud VM has no `MY MOVIES` tree and no source media; backfill must be run where the files live (the PC), or the files uploaded to the VM first.
